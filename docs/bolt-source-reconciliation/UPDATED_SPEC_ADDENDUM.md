## 2. متطلبات توسعة ينبغي فحصها حتى لو لم يذكرها النص الأصلي بالاسم

هذه مرشحات واجبة التحقق في الكود والمصادر، وليست ادعاءً بأنها غير موجودة أو مكتملة:

1. سياسة إخفاء المبالغ في واجهة العميل مع إعداد إداري صريح ومتسق عبر السلة وتفاصيل الطلب وPDF وAPI وRPC والكاش، دون حذف السجلات المالية من النظام.
2. شارة السلة: عدد خطوط الأصناف الفريدة منفصلًا عن مجموع الوحدات.
3. إظهار القيم المفقودة وغير الصالحة في تحليلات أونكس، بدل تحويلها إلى صفر أو إسقاطها بلا أثر.
4. ثبات حدود التقريب ودقة العملة بين شاشة كشف الحساب وPDF وExcel ومصدر SQL.
5. منع نجاح زائف في كتابة المنتجات والطلبات: إظهار failure/retry، وقراءة البيانات بعد الحفظ لإثباتها.
6. حماية الأسعار من التسرب عبر الكاش والعمل دون اتصال وواجهات RPC/JSON/التصدير.
7. إعادة محاولات Outbox والإشعارات بشكل idempotent مع معرّفات تسليم حقيقية.
8. محرك استيراد موحد يدعم المعاينة والمطابقة والتكرار والاستئناف وتقسيم الملفات وسجل صفوف مقبولة/مرفوضة.
9. ملفات الحساب والعناوين وأعضاء الشركة وعناوين التسليم إن كانت ضمن نطاق متجر B2B الجاري، مع RLS واختبارات عزل.
10. تنظيف محتوى Excel/PDF لمنع Formula Injection، ومعالجة ملفات غير موثوقة وPrompt Injection.
11. مساعد AI خاص بالعمل مع حدود مؤسسية وسجل تدقيق وتنقية البيانات، مع فصل واضح بين الاقتراح والتنفيذ.
12. الأصول المرجعية للشاشات واللقطات والاختبارات وسجل الميزات، ما دامت تساعد على استكمال التطبيق ولا تُستعمل بدل الكود الحقيقي.
13. إدارة الحالات الناقصة والحالات الفاشلة لكل واجهة: تحميل، لا توجد بيانات، خطأ، بلا صلاحية، إعادة المحاولة، اتصال مقطوع، ونجاح مثبت.
14. حوكمة الاعتماديات المفتوحة المصدر وحصر التراخيص وتجنب إدخال مزودات مدفوعة دون موافقة.

## 3. قواعد الدمج التي تمنع ضياع العمل

- لا تعالج الفرق فقط حسب اسم الملف؛ افحص path + blob/content + التاريخ + مكان الاستدعاء + اختبار الوظيفة.
- إذا تطابق الملف بين أكثر من مصدر فاحتفظ بسجل المصدر ولا تنشئ نسخة ثانية.
- إذا كان المسار نفسه بمحتوى مختلف، لا تنفّذ overwrite؛ قارن التعديلات واقتبس المنطق الصحيح في تطبيق واحد ثم اختبره.
- احتفظ بالأكواد الجزئية النافعة، لكن لا تضع ملفات غير مكتملة في مسار تشغيل الإنتاج دون feature flag أو ربط واضح يمنع الضرر.
- لا تخلط أنظمة تسجيل دخول أو Supabase projects أو متغيرات بيئة من مستودعات مانحة. انقل المنطق بعد مواءمته مع خدمات Nasr1 الحالية.
- المهاجرات التاريخية لا يعاد ترتيبها أو حذفها؛ أي تغيير جديد يكون migration جديدة متوافقة. قارن سياسات RLS وgrants وtriggers وRPC signatures والقيود والفهارس.
- لا تستورد بيانات الإنتاج من نسخة مانحة. المطلوب غالبًا كود/ميزات، وليس نسخ بيانات العملاء أو الفواتير أو الأسرار.
- لا تستخدم fixture أو mock لإثبات الوظيفة في التطبيق الحقيقي. بيانات التجربة تظل مميزة عن بيانات العمل.
