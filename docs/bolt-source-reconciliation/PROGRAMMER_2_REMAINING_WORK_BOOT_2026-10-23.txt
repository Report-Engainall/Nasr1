## 1. التكليف والقواعد

نفّذ النواقص الفعلية في المجال الخلفي والماليات والمخزون/Onyx والاستيراد/التصدير وDQS والذكاء الاصطناعي والتشغيل. لا تكتفِ بالتقارير ولا تعِد بناء ما ثبت عمله. استمر إلى الفجوة التالية تلقائيًا.

- اقرأ main وPRs وchanged files ونتائج CI الحية قبل التعديل؛ لا تنقل PASS من SHA تاريخي.
- لا تكتب مباشرة إلى main ولا تستخدم reset/clean/force-push. فرع P2 مع PRs صغيرة ومتسلسلة.
- قبل لمس migration أو RPC أو API أو package.json أو workflow أو ملف مشترك، سجّل Task ID والمالك والمسارات وbase SHA والاختبارات وشرط فك القفل. لا تعمل بالتوازي على الملف نفسه مع P1.
- CURRENT_EXECUTION_STATE.md هو مصدر next_task_id الوحيد ويملكه P2. حدّثه بعد إثبات الإغلاق فقط، ولا تنشئ مؤشرًا ثانيًا.
- لا بيانات مالية تجريبية أو قيم صفر بديلة عن مجهول، ولا تغيير على الإنتاج، ولا أسرار داخل Git.
- لا تعتمد على route أو component أو migration وحدها كدليل اكتمال. المطلوب عقد فعلي وصلاحيات وفشل صريح واختبار على SHA محدد.
- اختبارات الواجهة الشاملة عبر Bolt New مؤجلة حتى إكمال كود P1 وP2.

## 2.1 تغطية الوثيقة الأصلية كاملة

راجع جميع أقسام `AGHBARI-MASTER-PROJECT-SPECIFICATION.md` بندًا بندًا ضمن مجال P2، وليس فقط الـPRs المفتوحة أو الصفوف الحالية في المصفوفة. اربط كل مطلب بواجهة/خدمة/RPC/schema/RLS/role/tenant واختبار وإثبات، ثم سجّل حالته. أي متطلب من الوثيقة غير موجود في المصفوفة يجب إضافته بعد قفل الملف وتعيين المالك. صنّف الحالة COMPLETE/PROVEN أو PARTIAL أو WEAK أو DISCONNECTED أو MISSING — BACKEND EXISTS أو MISSING — NO VERIFIED CONTRACT أو BLOCKED EXTERNALLY. لا تستعد Bolt أو أرشيفاته في أي مرحلة.

## 2. نطاق التنفيذ: إكمال الوثيقة الأصلية فقط

الهدف هو إغلاق المتطلبات الوظيفية غير المنجزة في `docs/canonical/AGHBARI-MASTER-PROJECT-SPECIFICATION.md`، وفق `docs/canonical/AGHBARI-REQUIREMENT-REGISTRY.md` ومصفوفة القبول وسجلات التنفيذ الحية.

- **ممنوع استعادة أعمال Bolt**: لا تنزيل أرشيفات، ولا فكها أو فحصها أو مطابقتها، ولا استعادة واجهات من نسخ Bolt، ولا استخدام وقت P2 في استعادة snapshots. هذا خارج التكليف.
- لا تجعل أي مهمة استعادة أرشيف أو مقارنة archive blocker أمام استكمال المواصفة. اتبع متطلبات الوثيقة من الكود الحالي وما أثبتته سجلات Nasr1.
- ابدأ من `CURRENT_EXECUTION_STATE.md` و`next_task_id` الحالي بعد التحقق من main والـPRs؛ تحقق من كل ادعاء اكتمال على الشجرة الحية.
- لكل متطلب، حدد الشاشة/العملية، الخدمة، RPC/API، schema/RLS/tenant/role، التدقيق/idempotency، حالات الفشل واختبار القبول. عالج النقص الفعلي فقط.
- استخدم سجل المصدر الموجود كمرجع تاريخي عند الحاجة لتفهم قرار تنفيذ قائم فقط؛ لا توسع المهمة إلى إعادة جرد أو استعادة مصادر/أرشيفات.

تُعاد قراءة metadata والـhead/base والملفات ونتائج Actions قبل أي قرار. هذه قواعد منع ازدواج، وليست موافقة على دمج أعمى:

- **#56 مقابل #46:** #56 المرشح لمعالجة النجاح الزائف عند تحديث صفر صفوف بحالة الطلب. #46 مرجع أقدم. راجع تأثير الكتابة وtenant/RLS والاختبارات ثم احسم نسخة واحدة. نسّق مع P1 على واجهة الإدارة؛ لا تغيّر ملفاته دون handoff.

## 5. Onyx والمخزون

- تتبع مصدر Onyx وexternal IDs وtenant IDs من الاستيراد/اللقطة إلى تصدير الطلب وسجل التدقيق. ميّز snapshot محفوظًا عن محاولة مزامنة وحالة/خطأ محفوظين وعن نجاح live sync مثبت.
- أثبت ذرية preview/apply/rollback وحداثة snapshot/hash لحظة الكتابة، row/advisory locks، idempotency، حماية المحجوز، مستودع/مؤسسة صحيحين، منع المخزون السالب، حركات append-only وaudit.
- rollback تعويضي ولا يمحو حركات أحدث. اختبر التزامن، stale snapshot، replay بمفتاح/حمولة مختلفة، مستودعًا غير صحيحًا ودورًا غير مخول.
- قالب Onyx المستهدف: 27 عمودًا بترتيب ثابت؛ حافظ على IDs والأصفار البادئة كنص، اترك المجهول فارغًا، وامنع formula injection. لا تدّع توافق استيراد Onyx الفعلي دون تجربة مصرح بها ونتيجتها. عند نقص الوصول: BLOCKED_EXTERNAL.

## 6. المالية والمستندات

أكمل الفجوات المثبتة في دورة دفتر الأستاذ، الحسابات، القيود draft/post/void/reversal، اتزان debit/credit، دقة التقريب والعملة، المصدر والتدقيق وidempotency؛ ثم الفواتير والمدفوعات والتخصيصات والذمم وكشوف الحساب والمتأخرات والمصروفات والمرتجعات والإشعارات الدائنة والطباعة/PDF.

كل قيمة تستند إلى مستند/حركة محفوظة، ولا تكرر الرصيد بين المصدر المحاسبي واللقطات. تحقق من pagination الكاملة وعزل المؤسسة وصلاحية الدور وإظهار المبالغ وفق الإعداد. #62 يعالج parity محددًا للإشعارات الدائنة بكشف العميل؛ لا تكرر هذا الإصلاح ولا تعتبره دليلًا على اكتمال كل المحاسبة. لا تنفذ ردًا نقديًا أو ترحيلًا تلقائيًا بلا إذن صريح ومسار اعتماد. لا تستنتج ضريبة أو FX أو تكلفة غير معروفة.

## 7. الاستيراد والتصدير وجودة البيانات

- استخدم pipeline واحدًا: upload → staging → detection/mapping → validation → preview → commit → resume/reconciliation؛ لا تنشئ محركًا ثانيًا.
- اختبر idempotency للملف والطلب، hashes، resume/rollback، أخطاء الصفوف والحدود الفعلية للحجم والصفوف والأعمدة وطول الخلية.
- حافظ على SKU وcustomer/supplier external IDs والأصفار البادئة كنص. CSV يرفض quoting المشوه؛ CSV/XLSX محميان من formula injection دون تحويل الأرقام السالبة الصحيحة إلى نص.
- DQS مبني على checks قابلة للقياس ومحفوظة؛ يجب أن تتطابق معاينة الواجهة مع قيمة الخادم/DB. اختبر تواريخ غير ممكنة ومفاتيح الربط والحقول المطلوبة والقيم المجهولة دون تحويلها إلى صفر.
- راجع #59/#60/#63 واستعمل الاختبارات الموجودة بدل التكرار.

## 8. مركز المهام والطباعة والتقارير والذكاء

- تحقق من توليد المهام من أحداث حقيقية في المجالات التي لم تغطَّ بعد. مهام الشراء/الاستلام وفرق الجرد موجودة؛ لا تكررها. استخدم source ID ثابتًا ومنع التكرار عند إعادة المحاولة.
- الطباعة تطابق مرشحات الشاشة وصلاحيات الدور والمؤسسة وpagination؛ فرّق بين الصفوف المعروضة حاليًا وكل الصفوف المسموح بها.
- اربط كل KPI بمصدر محفوظ وفترة ووحدة/عملة وطريقة حساب، وتجنب double counting بين snapshots والدفتر.
- الحسابات المالية والمخزنية حتمية في DB/domain؛ AI يشرح الأدلة ولا يختلق أرقامًا أو يكتب قيودًا أو يغير المخزون. اختبر tenant/role، أقل payload، quota/rate limits، timeout/provider failure، fallback مجاني/محلي عند توفره، وusage ledger. لا تجعل مزودًا مدفوعًا شرطًا لتشغيل المتجر.
- PWA: احتفظ بحماية MIME؛ offline للقراءة/المسودات لا لاعتماد طلب أو دفع أو حركة مخزون، ولا تخزن auth/API/البيانات المالية الحساسة.
- WhatsApp لا يعرض Sent إلا بعد رد حقيقي من مزود رسمي. outbox retries محدودة وidempotent. لا تدّع Onyx/WhatsApp live integration دون استجابة موثقة.

## 9. النسخ الاحتياطي والتشغيل والتسليم

أكمل OPS-DR-001 بتمرين backup/restore معزول وسجّل بصمة artifact والوقت والنتيجة والمقاييس المقاسة. راجع #48 بدل إنشاء script جديد. وثّق API/RPC/workers وصلاحياتها ومدخلاتها ومعدلاتها وإعادة المحاولة والأخطاء والتدقيق، ثم تعليمات التشغيل والاختبار والنشر والتراجع وenv example دون قيم سرية. لا تستخدم الإنتاج ولا تغيّر إعدادات الأمان لإرضاء harness.

## 10. أدلة الإغلاق والملكية

لكل دفعة شغّل اختبار وحدة/عقد؛ واختبار PostgreSQL 17/RLS معزولًا عند تغيير DB أو الصلاحيات؛ وCore CI على SHA النهائي. سجّل Task ID، السبب الجذري، changed paths، SHA، روابط Actions، نتيجة كل job، والفجوات NOT RUN/BLOCKED_EXTERNAL. إذا فشل Playwright قبل بدء التطبيق بسبب Supabase أو image pull أو credentials، سجّل السبب الفعلي ولا تصفه PASS ولا تخفف RLS.

P2 يملك CURRENT_EXECUTION_STATE.md وWORK_COORDINATION.md وتقرير P2 وسجلات/اختبارات المالية وOnyx والمخزون والاستيراد/DQS/AI/العمليات. P1 يملك سجلات المصدر وواجهة التجارة ضمن نطاقه. المصفوفة مشتركة: سجّل قفلًا قبل تحريرها ولا يعمل عليها المبرمجان بالتزامن. لا تعدل سجلات P1 دون handoff.

حدّث المؤشر الوحيد بعد دليل الإغلاق، ثم تابع مباشرة إلى أول فجوة P2 مفتوحة مستقلة. احتفظ بحالات IMPLEMENTED وINTEGRATED وTESTED_EXACT_SHA وBROWSER_PROVEN وPRODUCTION_PROVEN منفصلة.

**معيار النجاح:** لا ازدواج للقدرات؛ مالية ومخزون آمنان ومدققان؛ import/export يحافظ على البيانات؛ كل إغلاق له دليل على SHA محدد؛ وجولة Bolt New الشاملة تأتي بعد اكتمال البرمجة لا بدلًا عنها.
