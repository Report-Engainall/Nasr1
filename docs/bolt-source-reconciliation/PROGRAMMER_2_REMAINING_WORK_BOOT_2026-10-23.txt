## 4. المسارات البرمجية المتبقية — سد فجوات لا بناء جديد

### A. Onyx والمخزون — INV-009
- أثبت على الشجرة الحالية ذرية apply تحت row lock، وحداثة snapshot/hash عند التطبيق لا المعاينة فقط، حماية الكمية المحجوزة، عزل المستودع والمؤسسة، منع إعادة التطبيق/تعارض الحمولة، حركات مخزون وaudit append-only.
- التراجع تعويضي ولا يمحو حركات أحدث. اختبر السباق بين جلسات مستقلة، stale snapshot، replay، warehouse/tenant mismatch، ودور غير مخول.
- افصل بين snapshot محفوظ ومحاولة مزامنة ونجاح مزامنة حي مثبت. لا تدّع Onyx live sync أو نجاح استيراد مستهدف دون credentials/response/receipt حقيقي.
- حافظ على قالب XLSX التفصيلي ذي 27 عمودًا وsource identifiers والأصفار البادئة كنص. يوجد اختبار formula safety مرشح في #63؛ تجنب التكرار.

### B. المالية ودورة المستندات
- تحقق من دورة دفتر الأستاذ بالكامل: chart of accounts، journal draft/post/void/reversal، اتزان debit/credit، currency/minor-unit rounding، صلاحيات المؤسسة والدور، source linkage، idempotency والتدقيق.
- أكمل الفجوات الفعلية فقط في فواتير المبيعات والمدفوعات والتخصيصات وكشوف الحساب والمتأخرات والمصروف النقدي ومردودات العميل والإشعارات الدائنة وPDF/الطباعة.
- PR #62 يعالج احتساب credit memo المرحّل في كشف حساب العميل. لا تعِد هذا الإصلاح؛ استخدمه جزءًا من دورة قبول أشمل.
- لا ترحّل القيد أو تنفذ دفعة/ردًا نقديًا تلقائيًا دون مسار موافقة موثق. لا تستنتج ضريبة أو سعر صرف أو تكلفة إذا كانت غير معروفة؛ لا تولّد بيانات مالية تجريبية.

### C. الاستيراد والتصدير وDQS
- استخدم محرك الاستيراد الحالي: upload → staging → detection/mapping → validation → preview → commit → resume/reconciliation. لا تضف محركًا موازيًا.
- اختبر idempotency لطلب/ملف الاستيراد، hashes، استئناف الـchunks، أخطاء الصفوف والrollback، وحدود الملفات والذاكرة الواقعية.
- حافظ على أكواد SKU/customer والأصفار البادئة كنص؛ CSV parser يرفض الاقتباس المكسور بدقة. احمِ CSV/XLSX من formula injection دون تحويل الأرقام السالبة المشروعة إلى نصوص.
- DQS يجب أن يكون مشتقًا من قواعد مقيسة وقابلة للتفسير ومخزنة؛ واجهة المعاينة يجب أن تطابق نتيجة الخادم/DB. PR #59 يعالج parity؛ أغلقه ولا تكرر خوارزمية أخرى.

### D. مركز المهام والطباعة
- تحقق من مصادر الأحداث المحفوظة لباقي المهام: الطلبات، الفواتير غير المسددة، RFQ، فشل الاستيراد، حالات المخزون والمرتجعات، مع source ID وtenant وrole/assignee/priority/due date/status وdeduplication. مهام الشراء/الاستلام وفرق جرد المخزون موجودة؛ لا تعِد توليدها.
- طباعة الفواتير وكشف الحساب والإشعار الدائن ومركز المهام يجب أن تطابق صلاحيات وفلاتر الشاشة، pagination/print-all المصرح، Arabic RTL/A4، وعدم التسرب بين المؤسسات.
- أبق اختبارات UI اليدوية الشاملة إلى جلسة Bolt الختامية؛ أصلح الآن أخطاء العقد الخلفي أو unit/contract التي تكشف فجوة محددة فقط.

### E. التقارير والذكاء الاصطناعي والحوكمة
- كل KPI يقرأ مصدرًا محفوظًا موثوقًا مع timeframe وunit/currency/methodology. لا تكرر snapshot مع دفتر الأستاذ ولا تعرض أرقامًا افتراضية.
- SQL/domain logic هو المرجع للحسابات المالية والمخزون والتوقعات الأساسية؛ AI يفسر الأدلة ويعرض حدود الثقة ولا يكتب قيودًا مالية أو مخزونًا تلقائيًا.
- أثبت tenant/role permission، أقل قدر من البيانات المرسلة للمزود، fail-closed عند timeout/rate-limit/auth failure، fallback مجاني/محلي إذا كان متاحًا، usage ledger بأرقام مقاسة أو NULL، وحدود الاستهلاك. لا تجعل API مدفوعًا شرطًا لتشغيل التجارة.
- أكمل الصفحات التي ما زالت disconnected من تقارير/AI فقط بعد تتبع كامل UI → service/provider → output evidence.

### F. PWA والإشعارات والعمليات والتسليم
- PR #64 يغطي حراسة MIME في cache؛ لا تعِد التنفيذ. راجع بقية التسريب المحتمل: لا تخزين للمصادقة أو API/financial responses؛ Offline للقراءة والمسودة، وليس لإنشاء طلب/دفع/تأكيد مخزون دون تحقق خادمي.
- WhatsApp لا يظهر Sent إلا بعد response/ID من المزود؛ outbox bounded retries/idempotent. مزامنة Onyx لا تثبت بإعداد أو زر.
- OPS-DR-001: شغّل backup/restore drill معزولًا واحفظ بصمة artifact ووقت الاستعادة والنتيجة والمقاييس الفعلية. افحص PR #48 بدل إنشاء script ثانٍ. لا تمس production.
- API-OPS-001 وHANDOVER-001: حصر نقاط API/RPC/workers، توثيق auth/tenant/role/idempotency/rate/error contracts وإجراءات التشغيل/التراجع، env example بلا أسرار، وحدود المجاني/المدفوع. حدّث النواقص فقط.
