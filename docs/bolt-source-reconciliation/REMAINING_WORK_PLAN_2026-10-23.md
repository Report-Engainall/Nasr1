## 1. قاعدة التنفيذ الملزمة

- لا تُعامل أي فقرة قديمة في التقارير كحقيقة حية إذا خالفت GitHub الحالي. عند بدء التنفيذ افحص رأس main والـPRs ونتائج CI مرة واحدة؛ بعد ذلك تابع من سجل المصفوفة وسجلات المهام بدل إعادة استكشاف المستودع كاملًا.
- لا يعاد تنفيذ أي قدرة مدمجة ومثبتة، بما فيها: التحويل المخزني متعدد الأصناف، حاجز بكسلات صور المنتجات، أساس خصوصية أسعار البطاقات والتفاصيل والمفضلة والمقارنة، تدفقات المرتجعات المرتبطة بالمصدر، دعوات/عضويات الشركة الأساسية، استلام المشتريات ومسودة القيد المحاسبي المرتبطة به، مهام المشتريات والاستلام، واختبارات السلة ومراجعة الطلب. يعاد فتح أي منها فقط عند وجود فشل حالي أو فجوة موثقة محددة.
- المكوّن أو الصفحة أو migration أو RPC وحدها لا تعني اكتمالًا. تُنفّذ الفجوة الحقيقية عبر الواجهة والخدمة والعقد الخلفي والصلاحيات وحالات الفشل والاختبار الملائم.
- الهدف تطبيق واحد داخل Nasr1. لا إنشاء متجر أو قاعدة بيانات أو مشروع Supabase موازٍ، ولا كتابة إلى المستودعات المانحة، ولا direct push إلى main أو force-push أو reset/clean.
- لا بيانات مالية تجريبية أو أرصدة/فواتير مختلقة؛ المجهول يبقى NULL/غير متاح، لا صفرًا مصطنعًا. لا نضيف اشتراكًا مدفوعًا أو اعتمادًا مدفوعًا لازمًا لتشغيل التجارة.
- كل تغيير مشترك يحتاج مالك مسار واحدًا وقفلًا موثقًا قبل التحرير. لا تعمل نسختان من المبرمجين على الملف نفسه. لا تُدمج فروعًا متداخلة بالتزامن.

## 3. تقسيم الملكية بلا تعارض

### P1 — التجارة وواجهة العميل والإدارة ومصادر الدمج

1. تدقيق عناصر الدمج المصدرية غير المحسومة فقط وإتمام دلالات order-input/الميزات المصدرية المتبقية، مع provenance وقرار مصدر ومختبر على الهدف.

3. استكمال قبول الشاشات وتوصيل الأفعال في واجهة العميل والتجارة: الكتالوج والبحث والتصنيف وتفاصيل المنتج والمفضلة والمقارنة والسلة والـcheckout والطلبات وإعادة الطلب والعروض/الاقتباسات والباركود وملف العميل/الشركة، وواجهات الإدارة التجارية للمنتجات والتصنيفات والعملاء والشركات والموظفين/الأدوار والطلبات/التسعير. نفّذ فقط الأجزاء التي تثبت أنها غير مكتملة على main.
4. تدقيق التنقل والحالات المرئية RTL/الاستجابة وإظهار الأخطاء/التفويض/التحميل/الفراغ وإعادة المحاولة، وربط كل فعل بعقد فعلي وعدم الادعاء بنجاح غير مؤكد.

مسارات ملكية P1: ملفات SOURCE_INTEGRATION_LEDGER.csv وREADY_TO_REUSE_FILE_AUDIT.csv وتقرير/مدخل P1، ومسارات واجهة التجارة/العميل والإدارة التجارية بعد فحص lock. لا يعدل P1 مسارات P2 المالية/Onyx/import/AI أو ملفات حالة P2.

## 4. طريقة الإنجاز وتخفيف هدر الوقت

1. ابدأ من الحالة الحية والـPRs الحالية؛ لا تعِد جرد كل الملفات أو تشغيل كل workflow كل مرة.
2. اختر مجموعة تغييرات مستقلة من نطاقك، وافحص فقط الملفات والتبعيات اللازمة لها.
3. قبل لمس ملف مشترك، تأكد من قائمة ملفات PRs المفتوحة وقفل المالك. إذا كان الملف مقفولًا، غيّر ملفًا مستقلًا أو اطلب handoff واضحًا ولا تنتظر.
4. لا تنفّذ Playwright/الجولات اليدوية عبر Bolt أثناء البرمجة ولا تصرف نقاط Bolt على الاستكشاف أو إصلاحات يمكن إجراؤها من GitHub. الاختبارات السريعة والوحدة/قاعدة البيانات وCore CI تُستخدم عند الحاجة لإثبات التغيير وتحديد الانحدار، لا لتكرار دورة كاملة بلا تغيير.
5. إذا فشل Browser job قبل بدء التطبيق بسبب سحب image/تهيئة البيئة، سجّله كـENVIRONMENT_BLOCKED وليس PASS ولا فشلًا في المنتج؛ تابع الأعمال المستقلة. إذا كشف الاختبار خطأً فعليًا داخل التدفق، أصلحه باختبار مركز بدل إعادة الفحص الشامل.
6. بعد اكتمال التنفيذ البرمجي وإغلاق فجوات الوثيقة، نفذ جلسة UAT واحدة مجمعة في Bolt New: الشاشات ومسارات الاستخدام والأدوار/المؤسسات والحالات الحدّية. لا تجرِ جلسة Bolt الآن. توقيت الجلسة بعد اكتمال البرمجة (متوقع بعد يومين من الإغلاق الفعلي أو حسب اكتماله)، وليس بعد تاريخ ثابت يسبق الإكمال.
7. لا يُعلن أي ادعاء أعلى من دليله: IMPLEMENTED ≠ INTEGRATED ≠ TESTED_EXACT_SHA ≠ BROWSER_PROVEN ≠ PRODUCTION_PROVEN. لا عمليات إنتاجية أو Onyx live sync أو WhatsApp send إلا بإثبات منفصل.

## 5. شروط الإغلاق

- لا تُترك شاشة في مصفوفة القبول بدون حالة وقرار: CLOSED_WITH_EVIDENCE، OPEN_WITH_REASON، NOT_RUN، أو BLOCKED_EXTERNAL مع رابط/سبب دقيق.
- كل PR مملوك يجب إما دمجه بعد المراجعة والـchecks المطلوبة أو وسمه مكررًا/متجاوزًا وإغلاقه بأمان. لا تبقِ نسخًا متنافسة لنفس التغيير.
- سجّل changed paths، السبب الجذري، الأمر والنتيجة الفعلية، SHA الذي اختُبر، رابط CI، العمل المتبقي والعائق. لا تستخدم النجاح على SHA قديم لإثبات SHA جديد.
- عند الإنهاء، سلّم تقريرًا ختاميًا واحدًا يضم المنجز المتبقي الذي أُغلق حديثًا فقط، الأدلة، العوائق الخارجية، وقائمة UAT واحدة جاهزة لـBolt New.
