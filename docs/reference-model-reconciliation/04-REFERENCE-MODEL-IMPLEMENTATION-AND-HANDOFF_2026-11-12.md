## 2. التنفيذ الفعلي الذي أضيف

### 2.1 شجرة التصنيفات — IMPLEMENTED ON MAIN

أُضيفت واجهة التصنيفات الرئيسية والفرعية داخل المجموعة القائمة «الكتالوج والتسعير»، فوق علاقة `categories.parent_id` وعمليات RPC القائمة، دون جدول أو محرك بديل.

الملفات:

- `src/lib/admin-category-tree.ts`: تحويل parent_id إلى شجرة مع إبقاء السجلات اليتيمة أو الدائرية ظاهرة بعلامة مراجعة؛ البحث يحافظ على سياق الآباء.
- `src/lib/admin-category-tree.test.ts`: أربعة اختبارات وحدات لعلاقة الأب/الفرع، واليتيم/الدورة، وسياق البحث، والبحث الفارغ.
- `src/lib/admin-category-products.ts`: قراءة مرتبطة بالتصنيف ومحدودة إلى 100 صف وحقول غير مالية فقط. نطاق المؤسسة مأخوذ من جلسة المستخدم، وتظل RLS مرجع التفويض.
- `src/routes/admin_.categories.tsx` و`src/routeTree.gen.ts`: مسار `/admin/categories`.
- `src/lib/admin-access-matrix.ts`: إضافة الوجهة داخل مجموعة الكتالوج القائمة، وإتاحتها للأدوار التشغيلية فقط.
- `src/components/AghbariApp.tsx`: توصيل وجهة الإدارة وإزالة محرر التصنيفات المتداخل في مركز البيانات كي لا يوجد محرران لنفس البيانات.
- `src/aghbari.css`: تنسيق محدود النطاق لشاشة الشجرة، مع الحفاظ على الهوية العامة.
- `src/lib/admin-access-matrix.test.ts` و`src/lib/admin-dashboard-groups.test.ts`: تحديث عقود عدد الصفحات ومجموعة الكتالوج.

**ما حُفظ:** محرك التصنيفات الحالي، RPCs الإنشاء/التسمية/الأرشفة/الاستعادة، القارئ العام، محرر المنتجات، التسعير، المجموعات الست وبطاقاتها. لا migration ولا تغيير قاعدة بيانات أو إنتاج.

## 2.3 استيراد البيانات — إعادة استخدام الوظيفة القائمة

تمت مراجعة `src/components/UnifiedImportEngine.tsx` على HEAD اللاحق للوثيقة، وتأكد وجود سجل دفعات بالفعل داخل المحرك: اسم الملف وبصمة SHA-256 والمصدر والحالة وDQS وأعداد الصفوف والتاريخ وإمكانية الاستئناف. كما توجد قراءة لأخطاء الصفوف مع ترقيم صفحات (100 صف في كل طلب)، وعرض الأسباب، وRollback آمن للدفعات المكتملة عند الصلاحية.

**قرار التنفيذ:** لا تُنشأ صفحة Import Logs أو جدول/محرك سجل جديد. مدخل DataCenter إلى UnifiedImportEngine كافٍ كمصدر موحد؛ المتبقي هو تحسين اكتشاف هذا التبويب/الرابط إن كان غير واضح للمستخدم، مع إبقاء سجل الدفعات داخل المحرك نفسه.

## 3. تقسيم العمل المتوازي

### المسار A — ChatGPT: الكتالوج والبيانات ودمج الواجهات

الملكية: واجهات الكتالوج، DataCenter، تنقل الإدارة، المسارات العامة التي تستضيفها AghbariApp، وربط مكونات المسار B بعد اكتمالها.

الأعمال التالية:
1. قبول شجرة التصنيفات على SHA الحالي ومعالجة أي TypeScript/Vitest/route-tree/browser regression.
2. إكمال مداخل DataCenter وسجل دفعات الاستيراد وجودة البيانات، مع إعادة استخدام `UnifiedImportEngine` وقراءات السجلات القائمة.
3. جمع عمليات Onyx في مدخل واضح مع الفصل بين استيراد اللقطات، التحليل، المطابقة، والتطبيق؛ لا وصف Dry Run بأنه مزامنة حية.
4. استكمال إدارة دفعات صور المنتجات فوق `BulkProductImageUploader` و`product-image.ts` وفق القدرات الحقيقية الحالية (WebP فقط حيث هو المتاح).
5. تحسين مظهر الإدارة وإعدادات المزودين والنماذج ضمن حد الميزانية المجانية.
6. توصيل مخرجات المسار B بعد مراجعة عقودها وصلاحياتها واختبارها.

**ملفات مشتركة يملكها المسار A ولا يعدلها المسار B:**  
`src/components/AghbariApp.tsx`, `src/components/AdminPages.tsx`, `src/lib/admin-access-matrix.ts`, `src/routeTree.gen.ts`, `src/aghbari.css`, `src/routes/admin_*.tsx`.

### المسار B — المبرمج رقم 2 في Chrome: حوكمة الذكاء ومراقبة النظام

الملكية: مخرجات معزولة لحوكمة Prompts، تدقيق AI، probes صحة النظام، تشخيص الأخطاء، وشجرة معمارية قراءة فقط. الهدف مساهمة فعلية تقابل نصف نطاق العمل المتبقي دون تعديل ملفات المسار A.

**المصادر القائمة التي يجب البناء عليها لا تكرارها:**
- `src/lib/intelligence/system-health.ts`: محرك تجميع موجود. يتطلب probes مطلوبة وفريدة، حداثة التحقق، Evidence ID مطابقاً، وحالة VERIFIED / COMPLETE / ACCEPTABLE. لا ينشئ probes من تلقاء نفسه.
- `src/lib/error-capture.ts`: يحتفظ بآخر خطأ محلياً لمدة خمس ثوانٍ تقريباً؛ ليس سجل أخطاء دائم أو متعدد المستخدمين.
- `src/lib/runtime-error-reporting.ts`: يسجل حقولاً تشخيصية متحفظة ولا يرسل stack/URL/token/بيانات عملاء إلى مزود خارجي. هذا ليس جدولاً لسجل أخطاء.
- `src/lib/intelligence/ai-prompt-governance.ts`: منطق دورة حياة Prompt والتحقق من المحتوى والأسرار وبصمة SHA-256 وأربع عيون؛ التخزين الدائم append-only وunique مسؤولية قاعدة البيانات/الخادم.
- لا تُظهر أي محتوى Prompt أو أسرار أو بيانات عملاء في شاشة التدقيق.

**المخرجات المطلوبة من المبرمج رقم 2:**

1. **Prompt persistence:** افحص الجداول وRPCs وmigrations قبل أي إضافة. إن لم توجد persistence مكافئة، أنشئ migration وخدمات/اختبارات لحفظ الإصدارات وسجل تدقيق append-only وUNIQUE `(organization_id, prompt_key, version)`. اربط draft/submit/approve/reject/activate/retire بالفاعل والمؤسسة والسبب والبصمة. الإنفاذ server-side، مع four-eyes ومنع المؤلف من الاعتماد/التفعيل كما يفرض المحرك. لا تطبق migration في قاعدة Supabase الحية.
2. **AI audit:** اعتمد على ledger/audit حقيقي فقط؛ اعرض الحقول المصرح بها (وقت، الفاعل، المزود/النموذج، الحالة، fallback، استهلاك مثبت). لا تعرض النص الخام للـprompt أو payload أو أسرار المزود.
3. **System health:** أضف مصدر probes فعلياً يربط كل مكون مطلوب بوقت فحص وكمون وEvidence ID ومالك. المفقود/القديم/المكرر/غير المثبت يبقى UNKNOWN أو UNAVAILABLE؛ لا تنشئ اتصالاً وهمياً ولا تعرض HEALTHY لمجرد وجود دالة.
4. **Error log:** لا تجعل التقاط المتصفح المؤقت مصدراً لسجل دائم. ابحث عن مصدر persistently stored؛ إن لم يوجد عقد آمن فوثّق BLOCKED_NO_PERSISTENT_SOURCE بدلاً من اختراع أحداث. أي مخطط دائم جديد يحتاج حدود حجب PII وRLS/tenant وrate limiting وaudit.
5. **Architecture registry:** أنشئ projector قراءة فقط يشتق route/view/component/service/RPC/role من registries القائمة؛ لا تبنِ navigation registry يدوياً ثانياً ولا تعرض أسراراً.
6. **Developer AI/Patches/Audit/Settings:** مساحة مقيدة، تبدأ قراءة/اقتراح ومراجعة diff فقط. كل patch مربوط بمستودع/فرع/SHA/اختبارات ومخاطر وموافقة بشرية؛ لا push أو merge تلقائي إلى main. الرموز أسرار خادم فقط ولا تستخدم `VITE_*`.

## 4. قواعد الدمج والقبول

1. كل تغيير صغير مستقل ومثبت بـSHA دقيق.
2. لا يعمل المساران على الملف نفسه بالتوازي.
3. لا تُوصل شاشة إلى واجهة المستخدم إلا عبر صلاحية صحيحة ومصدر حقيقي وحالات loading/error/empty/unauthorized.
4. لا migrations متوازية للوظيفة نفسها، ولا تغيير مباشر في قاعدة البيانات الحية.
5. لا تُقبل شاشة إذا كانت تعرض data placeholders أو اتصالاً/صحة غير مثبتة.
6. بعد كل دمج، يُعاد جلب HEAD الحالي وتُربط كل نتيجة اختبار به أو بالـSHA المصدر الذي اختبرته.
