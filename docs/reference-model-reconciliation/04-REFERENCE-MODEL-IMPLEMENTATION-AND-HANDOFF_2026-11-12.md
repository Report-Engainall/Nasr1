الأعمال التالية:

2. إكمال مداخل DataCenter وسجل دفعات الاستيراد وجودة البيانات، مع إعادة استخدام `UnifiedImportEngine` وقراءات السجلات القائمة.
3. جمع عمليات Onyx في مدخل واضح مع الفصل بين استيراد اللقطات، التحليل، المطابقة، والتطبيق؛ لا وصف Dry Run بأنه مزامنة حية.
4. استكمال إدارة دفعات صور المنتجات فوق `BulkProductImageUploader` و`product-image.ts` وفق القدرات الحقيقية الحالية (WebP فقط حيث هو المتاح).

6. توصيل مخرجات المسار B بعد مراجعة عقودها وصلاحياتها واختبارها.

### المسار B — المبرمج رقم 2 في Chrome: حوكمة الذكاء ومراقبة النظام

الملكية: مخرجات معزولة لحوكمة Prompts، تدقيق AI، probes صحة النظام، تشخيص الأخطاء، وشجرة معمارية قراءة فقط. الهدف مساهمة فعلية تقابل نصف نطاق العمل المتبقي دون تعديل ملفات المسار A.

**المصادر القائمة التي يجب البناء عليها لا تكرارها:**
- `src/lib/intelligence/system-health.ts`: محرك تجميع موجود. يتطلب probes مطلوبة وفريدة، حداثة التحقق، Evidence ID مطابقاً، وحالة VERIFIED / COMPLETE / ACCEPTABLE. لا ينشئ probes من تلقاء نفسه.
- `src/lib/error-capture.ts`: يحتفظ بآخر خطأ محلياً لمدة خمس ثوانٍ تقريباً؛ ليس سجل أخطاء دائم أو متعدد المستخدمين.
- `src/lib/runtime-error-reporting.ts`: يسجل حقولاً تشخيصية متحفظة ولا يرسل stack/URL/token/بيانات عملاء إلى مزود خارجي. هذا ليس جدولاً لسجل أخطاء.
- `src/lib/intelligence/ai-prompt-governance.ts`: منطق دورة حياة Prompt والتحقق من المحتوى والأسرار وبصمة SHA-256 وأربع عيون؛ التخزين الدائم append-only وunique مسؤولية قاعدة البيانات/الخادم.
- لا تُظهر أي محتوى Prompt أو أسرار أو بيانات عملاء في شاشة التدقيق.

**المخرجات المطلوبة من المبرمج رقم 2:**

1. **Prompt persistence:** افحص الجداول وRPCs وmigrations قبل أي إضافة. إن لم توجد persistence مكافئة، أنشئ migration وخدمات/اختبارات لحفظ الإصدارات وسجل تدقيق append-only وUNIQUE `(organization_id, prompt_key, version)`. اربط draft/submit/approve/reject/activate/retire بالفاعل والمؤسسة والسبب والبصمة. الإنفاذ server-side، مع four-eyes ومنع المؤلف من الاعتماد/التفعيل كما يفرض المحرك. لا تطبق migration في قاعدة Supabase الحية.
2. **AI audit:** اعتمد على ledger/audit حقيقي فقط؛ اعرض الحقول المصرح بها (وقت، الفاعل، المزود/النموذج، الحالة، fallback، استهلاك مثبت). لا تعرض النص الخام للـprompt أو payload أو أسرار المزود.
3. **System health:** أضف مصدر probes فعلياً يربط كل مكون مطلوب بوقت فحص وكمون وEvidence ID ومالك. المفقود/القديم/المكرر/غير المثبت يبقى UNKNOWN أو UNAVAILABLE؛ لا تنشئ اتصالاً وهمياً ولا تعرض HEALTHY لمجرد وجود دالة.
4. **Error log:** لا تجعل التقاط المتصفح المؤقت مصدراً لسجل دائم. ابحث عن مصدر persistently stored؛ إن لم يوجد عقد آمن فوثّق BLOCKED_NO_PERSISTENT_SOURCE بدلاً من اختراع أحداث. أي مخطط دائم جديد يحتاج حدود حجب PII وRLS/tenant وrate limiting وaudit.
5. **Architecture registry:** أنشئ projector قراءة فقط يشتق route/view/component/service/RPC/role من registries القائمة؛ لا تبنِ navigation registry يدوياً ثانياً ولا تعرض أسراراً.
6. **Developer AI/Patches/Audit/Settings:** مساحة مقيدة، تبدأ قراءة/اقتراح ومراجعة diff فقط. كل patch مربوط بمستودع/فرع/SHA/اختبارات ومخاطر وموافقة بشرية؛ لا push أو merge تلقائي إلى main. الرموز أسرار خادم فقط ولا تستخدم `VITE_*`.
